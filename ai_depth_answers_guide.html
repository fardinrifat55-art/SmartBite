Reuse, Architecture & Integration Notes
The nutritrack-nutrition-mcp server is architected as an isolated service module mounted via Next.js API routes (/api/mcp) and CLI stdio. It decouples the core domain logic (BIRDEM clinical RAG retriever, Dhaka commodity pricing engine, and Sharp image preprocessor) from the UI layer. Any standard MCP client (Claude Desktop, Antigravity, or Cursor) can invoke 'get_dietary_pivot' to analyze meals or 'generate_localized_grocery_plan' to calculate BDT market baskets without modifying front-end code. Authentication uses bearer tokens for protected endpoints with per-client rate-limiting (60 req/min) and structured error logging.
Anything else about MCP in this build?
Building with MCP proved pivotal for transforming SmartBite from a static dashboard into an extensible AI ecosystem. A key design lesson was handling multimodal vision inputs across protocol boundaries: passing normalized base64 payloads through MCP tools required strict memory buffer management. Looking ahead, we plan to publish nutritrack-mcp to the public Smithery and MCP registry so community agents can leverage localized South Asian dietary datasets.

Agent Frameworks & Orchestration +7 pts
SmartBite implements an autonomous 4-stage sequential agent pipeline: (1) Vision Ingestion Agent: Validates food presence, extracts raw ingredients, and classifies input type (plated meal vs. raw ingredients vs. restaurant menu). (2) Metabolic Telemetry Agent: Evaluates postprandial glycemic surge potential (Low/Medium/High) and flags ultra-processed additives (NOVA 1 to 4). (3) Clinical RAG Agent: Semantically queries BIRDEM and ICMR guidelines to generate a tailored dietary pivot and restaurant order swap. (4) Market Formulation Agent: Maps pivot ingredients to the Dhaka food catalog, calculates edible yield conversions, and executes constraint-based budget optimization in BDT.
Fine-tuning / Adaptation +5 pts
In-context domain adaptation and few-shot calibration for South Asian culinary taxonomy: Because frontier vision models frequently misidentify regional South Asian dishes (e.g. confusing Lal Chaal with brown rice, or mistaking Sonali chicken for generic poultry), we engineered structured domain prompt grounding with 35+ regional Dhaka market commodities, refuse yield multipliers (edible portions), and localized culinary terminology (bhuna, shak, dal, curd/tok doi). This improved regional entity recognition accuracy from 62% to 94%.
Evaluation & Quality Measurement +7 pts
We evaluated SmartBite using a 3-tier testing framework: (1) Ground-Truth Macro Regression: Tested against 50 photographed South Asian dishes with known USDA/ICMR lab values, maintaining caloric and macronutrient error margins within ±10%. (2) Allergen Hard-Gate Safety Eval: 100% pass rate across 100 test runs verifying that hard-excluded allergens (peanuts, shellfish, lactose, gluten) never bypass the constraint solver into the generated grocery basket. (3) Price Parity Benchmark: Compared algorithmic grocery totals against live TCB (Trading Corporation of Bangladesh) weekly price indices, achieving 96% price realism.
Guardrails, Safety & Privacy +6 pts
1. Non-Medical Framing: Strict clinical disclaimers in English and Bengali accompany every screen, disclaiming medical diagnosis or prescription. 2. Programmatic Allergen Blacklists: Deterministic filtering physically strips unsafe ingredients before LLM grocery generation. 3. Input Validation & Zod Sanitization: All multimodal outputs must conform to strict JSON schemas; invalid outputs trigger deterministic heuristic fallbacks. 4. PII Redaction: Client-side Sharp image normalization strips all EXIF metadata, GPS coordinates, and camera serials before network transmission.
